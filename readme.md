# intro
this is my latest project. and will be ongoing for a while.

# core idea
the idea is to make a full compiler from scratch only using minimal libraries like [nlohmanns json lib](https://github.com/nlohmann/json) and jarros [arg parser lib](https://github.com/jarro2783/cxxopts)

the goal is to understand *everything* in a compiler pipeline by building each stage manually instead of relying on existing compiler frameworks.

---

# compiler architecture
it will be like any other compiler and will be like:

- lexer  
  structures the source code into tokens by matching patterns (keywords, identifiers, literals, operators)

- parser  
  takes the tokens and structures them into a syntax tree (AST), removing ambiguity like parentheses grouping and operator precedence

- semantic analyzer  
  checks meaning of the program (types, variable existence, function calls, scope rules)

- intermediate representation (IR)  
  converts AST into a lower-level, simplified representation that is easier to optimize

- optimizer (optional but planned to come after the compiler is working)  
  applies transformations like constant folding, dead code elimination, and basic inlining

- code generator  
  converts IR into target output (starting with custom bytecode, later maybe x86 or ARM)

- backend / VM  
  executes or runs the generated bytecode (useful for testing before real machine code output)

# language goals
the language this compiler will support (temporary design goals):

- C-like syntax (familiar, simple to parse)
- strongly typed (no implicit chaos)
- minimal keywords
- no unnecessary features early on
- eventually support:
  - functions
  - structs
  - pointers 
  - basic standard library

---

# design decisions
- no compiler frameworks (no LLVM)
- minimal external dependencies
- handwritten lexer + parser (recursive descent or Pratt parser)
- simple custom IR instead of LLVM IR
- focus on clarity over performance

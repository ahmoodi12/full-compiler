# Data-Driven Compiler

My latest and most ambitious project.

The goal is to build a complete compiler from scratch while understanding every stage of the compilation pipeline. Rather than relying on large compiler frameworks, each component is implemented manually and designed to be as flexible and configurable as possible.

The project is written in C++ and heavily focuses on data-driven design.

---

# Core Idea

Most compilers hardcode language rules directly into source code.

This project takes a different approach:

* Lexer rules are defined through JSON.
* Parser behavior is driven by JSON-defined grammar and operator rules.
* Instruction sets will be defined through JSON ISA descriptions.
* Compiler stages are designed to consume data rather than embed language-specific logic wherever possible.

The long-term goal is to create a compiler framework capable of supporting multiple languages and targets with minimal code changes.

---

# Compiler Architecture

The planned pipeline:

```text
Source Code
    ↓
Lexer
    ↓
Parser
    ↓
AST
    ↓
Semantic Analysis
    ↓
IR
    ↓
Optimization
    ↓
Code Generation
    ↓
assembler
```

## Lexer

Converts source text into tokens.

## Parser

Builds an Abstract Syntax Tree (AST) from tokens.

## Semantic Analysis

Validates program meaning:

* Type checking
* Symbol resolution
* Scope validation
* Function checking

## Intermediate Representation (IR)

Converts AST structures into a simplified form that is easier to analyze and transform.

## Optimizer

Planned optimizations include:

* Constant folding
* Dead code elimination
* Basic propagation passes

## Code Generator

Generates target instructions using a configurable ISA description.

## Backend

Executes generated bytecode and serves as a testing platform before native machine-code generation.

# Design Goals

## Understand Everything

Every major compiler stage is implemented manually.

No LLVM.

No parser generators.

No lexer generators.

No compiler frameworks.

## Data-Driven First

Whenever practical, behavior should be controlled through configuration rather than hardcoded logic.

## Clarity Over Performance

The primary goal is learning, experimentation, and flexibility.

Performance improvements come later.

## Extensibility

The architecture should allow:

* Multiple source languages
* Multiple instruction sets
* Experimental language features
* Custom backends

---

# Planned Language

The initial target language is intentionally simple.

Current goals:

* C-like syntax
* Strong typing
* Functions
* Structs
* Pointers
* Arrays
* Minimal standard library

The design is expected to evolve significantly throughout development.
